## 发票与售后处理手册（2026 修订版）

> 本手册用于企业知识库客服助手的长答演示，覆盖发票、退款、物流、会员四类问题。
> 文中时效为工作日口径，节假日顺延。

### 一、处理时效与责任划分

不同问题类型的首次响应与处理完成时限不同，先看这张表再决定是自助处理还是转人工。

| 问题类型         | 首次响应 | 处理完成     | 责任团队   |
| ---------------- | -------- | ------------ | ---------- |
| 发票换开         | 2 小时   | 1 个工作日   | 财务票据组 |
| 发票重开（跨月） | 4 小时   | 3 个工作日   | 财务票据组 |
| 售后退款         | 1 小时   | 1-3 个工作日 | 售后一组   |
| 物流异常         | 1 小时   | 视承运商     | 售后二组   |
| 会员权益申诉     | 4 小时   | 2 个工作日   | 用户运营组 |

超过时效仍未推进的，按第七节的升级规则转人工，不要在同一条会话里反复承诺时间。

### 二、发票开具与换开

#### 2.1 开票前置条件

1. 订单状态必须是「已签收」或「已完成」，未签收的订单只能开预付款凭证
2. 抬头信息必须与营业执照或身份证件一致，个人抬头不需要税号
3. 一笔订单只能开一张发票，拆单开票需要先提交工单说明用途
4. 退款中的订单不允许开票，系统会在校验阶段直接拦截

#### 2.2 换开流程

电子普通发票开具后 **30 天内** 可以申请换开，超出 30 天只能走红冲重开。标准流程如下：

1. 核对开票主体与税号，确认与上次开票信息一致
2. 提交换开申请，附上原发票号码与换开原因
3. 财务审核通过后，原发票作废，新发票在 1 个工作日内开具
4. 新发票以邮件与站内信双通道下发，邮件可能进入垃圾箱
5. 收到后检查价税合计是否与原订单一致，不一致立即联系客服

校验规则在系统里是硬编码的，换开请求会先过一遍下面的判断：

```js
// 换开资格校验：三项全过才允许提交
function canReissue(invoice) {
  const withinWindow = invoice.daysSinceIssued <= 30
  const notRefunded = invoice.orderStatus !== 'refunding'
  const notBlank = Boolean(invoice.buyerName && invoice.taxNo)

  return withinWindow && notRefunded && notBlank
}
```

任意一项不通过时接口返回 `REISSUE_REJECTED`，前端要把具体原因展示出来，不要只弹一句「操作失败」。

#### 2.3 常见驳回原因

| 驳回原因       | 典型场景                                       | 处理建议                     |
| -------------- | ---------------------------------------------- | ---------------------------- |
| 抬头与证件不符 | 抬头带「有限公司」但营业执照是「有限责任公司」 | 按营业执照原文重填           |
| 超过 30 天     | 客户一个月后才想起换开                         | 转红冲重开，需财务复核       |
| 订单在退款中   | 客户一边退款一边要求换开                       | 先结束退款流程再开票         |
| 税号位数不对   | 税号少一位或多一位                             | 核对营业执照统一社会信用代码 |

### 三、退款与红冲

退款申请提交后，系统会按支付方式分流，到账时间与支付渠道强相关：

| 支付方式 | 预计时效      | 备注             |
| -------- | ------------- | ---------------- |
| 微信支付 | 1-3 个工作日  | 节假日顺延       |
| 支付宝   | 1-3 个工作日  | 原路退回         |
| 银行卡   | 3-7 个工作日  | 以银行入账为准   |
| 对公转账 | 5-10 个工作日 | 需要提供开户信息 |

需要注意的三点：

- 部分退款不会影响发票状态，全额退款必须同时处理发票
- 红冲后的新发票不能自动关联原订单，需要人工在工单里备注
- 退款进度以支付渠道回执为准，页面上的「已退款」只代表我方已发起

> 如果超过预计时效仍未到账，请先在工单里查询渠道回执，再联系支付渠道，不要重复发起退款。

### 四、物流异常处理

先确认轨迹是否真的停了，再判断是分拣异常还是丢件：

1. 查看物流轨迹是否超过 **48 小时** 未更新
2. 核对收件地址与联系电话是否完整，虚拟号失效会造成「派送失败」
3. 联系承运方确认是否发生分拣异常或地址超区
4. 确认丢件后提交工单，附上订单号与物流截图

| 异常类型     | 判断依据               | 处理方式               |
| ------------ | ---------------------- | ---------------------- |
| 长时间未更新 | 超过 48 小时无新轨迹   | 催件，2 个工作日内回复 |
| 派送失败     | 显示「联系不上收件人」 | 更新联系方式后重新派送 |
| 地址超区     | 承运商标注「超区不派」 | 转邮政或自提点         |
| 疑似丢件     | 超过 7 天无进展        | 全额赔付并补发         |
| 破损签收     | 签收时已拍照留证       | 按商品价值赔付         |

涉及赔付时请保留物流截图与商品价值凭证，凭证缺失会影响赔付额度审批。

### 五、会员与积分

会员等级按近 **12 个月** 的实付金额计算，权益包含专属客服通道、生日双倍积分、每月免运费券。

| 等级 | 年实付门槛 | 主要权益                     |
| ---- | ---------- | ---------------------------- |
| 银卡 | 1,000 元   | 免运费券 1 张/月             |
| 金卡 | 5,000 元   | 专属客服 + 免运费券 3 张/月  |
| 黑卡 | 20,000 元  | 专属客服 + 生日礼 + 优先发货 |

积分有效期为获取后 **24 个月**，过期前 30 天会通过站内信提醒一次。积分不能提现，也不能转赠，退款时按比例扣回。

### 六、高频问答

**Q：发票开错了，能直接改吗？**
A：不能。已开具的发票只能作废或红冲，改信息等于换开，按 2.2 的流程走。

**Q：退款到账了，发票还要处理吗？**
A：全额退款必须红冲发票，部分退款不影响发票状态。财务对账时会核对这两件事。

**Q：换开次数有限制吗？**
A：同一订单最多换开两次，第三次需要财务主管审批。

**Q：物流显示签收但我没收到怎么办？**
A：先联系承运商确认签收人，再提交工单。超过 24 小时未解决按疑似丢件处理。

**Q：积分过期了能恢复吗？**
A：过期积分不恢复。如果是系统原因导致未提醒，可以提交申诉，运营组按个案处理。

**Q：会员降级后权益什么时候失效？**
A：降级在次月 1 日生效，当月已领取的免运费券仍然可用。

**Q：对公转账退款为什么这么慢？**
A：需要走财务付款审批，涉及开户信息核对，5-10 个工作日属于正常范围。

**Q：可以开专用发票吗？**
A：可以，但需要提供一般纳税人资格证明，且订单金额需满 500 元。

### 七、升级与转人工

自助渠道解决不了的问题，按下面的规则升级，避免在同一条会话里无限循环：

1. 首次响应超时 → 升级到组长，附带会话链接
2. 涉及金额变更或发票红冲 → 直接转财务复核
3. 客户明确要求人工 → 不再尝试自助话术，立即转接
4. 同一问题被驳回两次 → 升级到主管，附带完整处理记录

升级时请在工单里写清楚三件事：客户诉求、已做过的处理、卡在哪一步。只写「客户不满意」的工单会被退回，反而更慢。

> 手册里的时效与金额门槛每年修订一次，以财务与运营的最新版本为准。

### 八、工单模板

写工单不是写作文，模板固定四段，缺一段就会被审核退回重写。

#### 8.1 退款类工单

```
【问题类型】售后退款
【订单号】SO-20261103-0042
【客户诉求】支付成功但未发货，希望全额退款
【已做处理】已确认库存为零，已联系仓库取消拣货
【卡点】金额超过 5,000 元，需要财务复核
【期望完成时间】2026-11-05 之前
```

#### 8.2 发票类工单

```
【问题类型】发票换开
【订单号】SO-20261028-0117
【原发票号】INV-8820136
【换开原因】抬头少写「有限责任公司」四个字
【附件】营业执照扫描件、客户确认聊天截图
【卡点】无，材料齐全，等待财务开具
```

模板里的「卡点」一栏最容易被写空，但只要卡点为空，审核就会默认「可以自动处理」，反而跳过人工。确实不卡的时候写「无」，不要留白。

### 九、质检与复盘

客服会话每周抽检一次，重点看四件事：

| 检查项   | 合格标准             | 常见扣分                   |
| -------- | -------------------- | -------------------------- |
| 首响时效 | 1 小时内首次回复     | 只发表情或「稍等」不算首响 |
| 结论明确 | 给出具体时效与下一步 | 通篇「帮您反馈」没有结论   |
| 信息准确 | 引用现行政策版本     | 用了过期的手册条目         |
| 处理闭环 | 工单有结果与回访     | 处理完不更新工单状态       |

复盘的目的是改流程，不是追责。同一条规则被三个人误解，说明手册写得不够清楚，应该改手册，而不是让三个人各写一份「注意事项」。

每次复盘输出三个结论就够了：哪条规则被误解、改成什么说法、下一版什么时候生效。写成十页 PPT 的复盘没人看，也不会被执行。

### 十一、审批额度对照

超过下面额度的一律需要上级审批，跳过审批提交的工单会被系统驳回，不会进入人工队列：

| 事项         | 免审批额度 | 审批人      | 审批时限   |
| ------------ | ---------- | ----------- | ---------- |
| 售后退款     | 500 元     | 组长        | 2 小时     |
| 售后退款     | 5,000 元   | 主管        | 4 小时     |
| 丢件赔付     | 1,000 元   | 组长        | 2 小时     |
| 丢件赔付     | 10,000 元  | 主管 + 财务 | 1 个工作日 |
| 发票红冲     | 不限金额   | 财务        | 1 个工作日 |
| 会员补偿积分 | 2,000 分   | 运营        | 4 小时     |

额度按「单笔订单合计」计算，拆分多笔规避审批属于违规操作，质检会重点抽查这一类。

### 十二、常见错误对照

| 错误做法             | 造成的后果                       | 正确做法             |
| -------------------- | -------------------------------- | -------------------- |
| 先承诺时效再查政策   | 承诺了做不到的时间，客户二次投诉 | 先查政策再给时限     |
| 让客户重复描述问题   | 体验差，且容易漏关键信息         | 开工单前先看历史会话 |
| 用「系统问题」当结论 | 客户不接受，也无法复盘           | 写清具体失败环节     |
| 退款和发票一起处理   | 两个流程互相阻塞                 | 先结束一个再开另一个 |
| 只改工单状态不写结论 | 复盘时查不到处理依据             | 状态与结论同时更新   |

### 附：使用本手册的三条约定

1. 术语与系统中的字段名保持一致，不要自创简称，否则检索命中率会明显下降
2. 涉及金额、时效、日期的表述必须写明单位与口径，工作日与自然日不能混用
3. 手册条目被引用时要带上章节号，方便在复盘会上直接定位到原文

以上三条看起来是格式要求，实际是检索质量的要求：知识库回答的可信度取决于条目能不能被准确命中，格式漂移会让召回结果错位。
